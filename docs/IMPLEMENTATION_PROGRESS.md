# تقدم التنفيذ — 6 سبتمبر 2026

بدأ تنفيذ خطة IMPLEMENTATION_PLAN.md. كل ما يلي تعديل ملفات ومراجعة مصدرية؛ لم يتم تشغيل التطبيق أو Python أو TypeScript أو الاختبارات أو migrations أو تثبيت أي حزمة.

## المنفذ في دفعة إصلاح الأساس

- توحيد UUID في عقود الطلب/الرد، وDecimal لرد البيع، وتحويل دور قاعدة البيانات عند إصدار JWT.
- migration جديدة 0002، دون تعديل 0001 أو تطبيق أي migration: توقيتات المستهدفات، نقاط عكسية غير صفرية، مفتاح idempotency مركب لكل مستخدم، مصدر طلب النقل، صلاحية المراجعة الحالية، وإصدار جلسة المستخدم.
- الجرد يحتفظ بالمخزون المرجعي ويسجّل حركة تدقيقية delta=0؛ الفرق يبقى في الملاحظة المستقلة. سعر البيع يأتي من الكتالوج حتى إن أرسل العميل سعرًا آخر.
- قفل/إنشاء رصيد المخزون باستخدام upsert ثم row lock. قفل حالة البيع قبل الإلغاء والطلب قبل القرار والتنفيذ. ترتيب أقفال الفروع في التحويل لتقليل التعارض.
- سياسة نطاق موارد مشتركة. منع المروّج من تغيير تكليفه أو إدارة/إلغاء المبيعات، وفلترة المبيعات والطلبات والصور والمهام والحضور بالمستخدم أو الفريق المسند، والتحقق من موارد المراجعة وملاحظات الصور. التدقيق للأدمن.
- فرع المشرف لا يقيّد إسناد المروّجين إلى نفس الفرع؛ علاقة supervisor_id هي مرجع الفريق. قراءة الفروع والمستهدفات تدعم هذا النطاق. المخزون يدعم اختيار فرع مصرح به.
- المعاملات في طبقة HTTP. خدمات الخادم تستخدم flush بدل commit، بحيث يُحفظ الإجراء ونتيجة replay وسجل التدقيق معًا قبل إرجاع نجاح العميل. خدمات تُستدعى خارج HTTP تحتاج معاملة والتزامًا صريحًا من المستدعي.
- جميع mutations في routers التشغيلية تتطلب Idempotency-Key؛ auth مستثناة. تدوير refresh له قفل مستقل. تكرار نفس العملية يعيد الرد المحفوظ، واختلاف المحتوى/النطاق يرفض إعادة استخدام المفتاح.
- قرارات طلبات المخزون تسجّل حالة الطلب وReview والإشعار معًا. مسار POST /requests/{id}/resubmit يصحح طلب changes_requested. تنفيذ relocate يطلب source_branch_id، ويتحقق منه ويخصم المصدر ويضيف الوجهة ذريًا.
- تاريخ المراجعات لا يحذف عند تغيير ملاحظات الصورة؛ المراجعات القديمة تصبح is_current=false. إسناد المهمة وتنفيذ الطلب ينتجان إشعارًا محفوظًا.
- حماية تعطيل آخر أدمن، وإعادة التفعيل على فرع/مشرف نشط، ودعم تعديل الدور مع حماية الفريق. تغيير التكليف/الدور وتعطيل الحساب وتغيير كلمة المرور يلغي الجلسات السابقة عبر auth_version وrefresh revocation.
- كلمة مرور إجبارية تمنع العمليات حتى تغييرها. production ترفض سر JWT الافتراضي/القصير. قراءة readiness تتحقق من DB. رسائل HTTP وأخطاء validation لها envelope موحد ولا تردد إدخال كلمة المرور.
- الصور لها endpoint محتوى محمي، وحد قراءة للرفع وفحص توقيع ملف أساسي. S3 يستخدم رابطًا مؤقتًا عند تهيئته لاحقًا. لا تمكين لخدمة S3 أو تثبيت boto3.
- تصحيح total في قوائم الطلبات والمهام والإشعارات. snapshot يفلتر نطاق بياناته ويصرّح بأن incremental sync غير مدعومة بعد.
- DemoProvider يحافظ على البيانات غير المقروءة بدل استبدالها تلقائيًا. Git ignore يستبعد ملفات Python المولدة وملفات Zone.Identifier الجانبية.
- seed محظورة في production، وتحتوي تكليفات مشرف وأرصدة بداية ومواعيد نهاية شهر صحيحة وأسماء منتجات عربية.
- تجهيز اختبارات آمنة تستخدم TEST_DATABASE_URL لقاعدة تنتهي بـ_test، وschema عشوائية مستقلة، ومعاملة خارجية لكل اختبار؛ إزالة drop_all على قاعدة التطبيق. كتابة regression للأنواع والصلاحيات وسعر الخادم وإعادة إرسال HTTP وتغيير التكليف غير المصرح به.

## العقد الحالي للربط القادم

- الحسابات: POST /api/v1/login، /refresh، /logout، /change-password؛ GET /api/v1/me. ليست /auth/login.
- التوكن في Authorization: Bearer. بعد تغيير كلمة المرور أعد تسجيل الدخول؛ الجلسات السابقة ملغاة.
- POST/PATCH/PUT/DELETE التشغيلية: Idempotency-Key فريد لكل فعل، ونفس المفتاح والمحتوى عند إعادة الإرسال. مدة replay حسب إعداد الخادم؛ لا إعادة استخدام مفتاح لإجراء جديد.
- الجرد: POST /api/v1/inventory/counts. الحضور: /api/v1/attendance/clock-in و/clock-out.
- الطلبات: /api/v1/requests/{id}/review و/cancel و/fulfill و/resubmit. تنفيذ النقل يحتاج source_branch_id، والتصحيح يستخدم نفس عقد RequestCreate.
- الصور: POST /api/v1/photos/upload؛ كل رابط محتوى في الرد يحتاج Authorization. القراءة المحمية /api/v1/photos/{id}/content.
- العقود التنفيذية في backend/app/schemas وbackend/app/api/routes هي المرجع الحالي. docs/api-contract.md التاريخية تتضمن اقتراحات غير مطبقة؛ يلزم توحيدها نهائيًا في مرحلة الربط.

## ما لا يزال مفتوحًا

لم يبدأ ربط الهاتف بالحساب الحقيقي أو تحويل الشاشات من DemoProvider إلى الـAPI. لم يتم إنشاء AuthProvider أو تخزين جلسة آمن أو recovery أو تفعيل البصمة. الواجهات الحالية ما زالت تجربة محلية بنفس شكلها وبياناتها.

ما زال مطلوبًا: إكمال اختبارات HTTP لكل الأدوار والتزامن وmigrations، مراجعة كل قواعد تعديل الحسابات تحت التزامن، rate limiting، تنظيف ملفات رفع فشلت معاملاتها، دورة حذف الصور وإحداثياتها، مكافأة التحديات وتحديث الترتيب، تفاصيل تقارير المؤسسة، طابور offline وsince/versioning، وتوحيد التوثيق بالكامل. تعريفات الصور والتخزين لا تمثل نشرًا فعليًا.

بعدها تأتي مراحل API client/Auth والربط التدريجي وواجهات الإجراءات الجديدة، ثم ملفات CI والبناء والنسخ الاحتياطي والمراقبة. لا توجد نتيجة اختبارات أو ضمان جاهزية إنتاجية في هذه الدفعة. التشغيل والتحقق الفعلي يظلان مؤجلين حسب تعليمات المستخدم.
